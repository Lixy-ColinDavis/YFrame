问题描述：Show_Log 方法通过静态委托 YF_Manager_Log.d_LogWrite 被调用，该委托可能从任意线程（后台工作线程、日志线程、插件线程）触发。 方法直接更新 LogText 属性，该属性绑定到UI元素。WPF 严格要求所有UI绑定属性的更新必须在UI（Dispatcher）线程上执行，从非UI线程更新会导致不可预测的行为或 InvalidOperationException。

    }
}

{

    {

            LogText += msg + "\n";

Assembly.LoadFrom 锁定插件 DLL，阻止运行时更新
Critical 插件系统资源管理 文件: UserControlsService.cs:80,155
问题描述：Assembly.LoadFrom(string path) 会锁定磁盘上的 DLL 文件，直到应用程序域卸载。 这意味着在应用程序运行期间，插件 DLL 无法被替换、更新或删除。对于插件化框架而言，这是一个严重的设计缺陷——用户无法在不重启应用的情况下热更新插件。

推荐使用 Assembly.Load(byte[]) 配合 File.ReadAllBytes() 加载程序集（读取到内存后释放文件锁）， 或者为每个插件使用独立的 AssemblyLoadContext（.NET Core 3.0+）以支持卸载。

🔴 当前代码

Assembly assembly = Assembly.LoadFrom(assemblyPath);  // ⚠️ 锁定DLL文件

Type userControlType = assembly.GetType($"{s}.MainControl");
Type ViewModelType = assembly.GetType($"{s}.MainControlViewModel");

🟢 修改建议

UserControlsService.cs — 使用 Assembly.Load(byte[]) 避免文件锁

// 将程序集读入内存，释放文件锁

DispatcherTimer 在非 UI 线程创建，Tick 事件无法触发
High 线程安全WPF 文件: PerformanceMonitor.xaml.cs:98-136
问题描述：DispatcherTimer 必须在拥有 Dispatcher 的线程（即 UI 线程）上创建。代码中在一个 new Thread 内创建 DispatcherTimer，该后台线程没有 Dispatcher。这会导致 Tick 事件可能永远不会触发，或抛出异常。 同时 UpdatePerformanceData 回调中调用 OnPropertyChanged（触发 UI 更新）也需要在 UI 线程上执行。

正确的做法是：后台线程仅用于初始化 WMI 查询和 PerformanceCounter，然后使用 Application.Current.Dispatcher.BeginInvoke 将 DispatcherTimer 的创建和启动封送到 UI 线程执行。

🔴 当前代码

PerformanceMonitor.xaml.cs — 构造函数
DispatcherTimer timer = new DispatcherTimer();

Thread thread = new Thread(() => {
    // ... WMI 查询 ...
    // ... PerformanceCounter 初始化 ...

    // ⚠️ timer 在非 UI 线程上创建和启动！Tick 可能永远不会触发
    timer.Interval = TimeSpan.FromSeconds(5);
    timer.Tick += UpdatePerformanceData;
    timer.Start();
});
thread.IsBackground = true;
thread.Start();

🟢 修改建议

PerformanceMonitor.xaml.cs — 后台线程仅做初始化，Timer在UI线程创建
public PerformanceMonitor()
{
    MainWindowViewModel.Instance.logger.LogInfo("性能监视器初始化-开始");
    InitializeComponent();

    // UI线程：初始化图表数据
    SeriesCollection = new SeriesCollection { /* ... */ };
    Labels = new[] { "25秒前", "20秒前", "15秒前", "10秒前", "5秒前", "现在" };
    YFormatter = value => value.ToString("N0");
    DataContext = this;

    // 后台线程：初始化WMI和PerformanceCounter（这些操作可能耗时）
    ThreadPool.QueueUserWorkItem(_ =>
    {
        InitializeCounters();

        // 将 Timer 的创建封送到 UI 线程
        Application.Current?.Dispatcher.Invoke(() =>
        {
            var timer = new DispatcherTimer
            {
                Interval = TimeSpan.FromSeconds(5)
            };
            timer.Tick += UpdatePerformanceData;
            timer.Start();
        });
    });

    MainWindowViewModel.Instance.logger.LogInfo("性能监视器初始化-完成");
}

private void InitializeCounters()
{
    // WMI 查询系统总内存
    using (var searcher = new ManagementObjectSearcher(
        new ObjectQuery("SELECT TotalPhysicalMemory FROM Win32_ComputerSystem")))
    {
        foreach (ManagementObject obj in searcher.Get())
        {
            totalMemoryMB = Convert.ToInt64(obj["TotalPhysicalMemory"]) / (1024 * 1024);
        }
    }

    MainWindowViewModel.Instance.logger.LogInfo(
        $"总系统内存：{totalMemoryMB}MB, {(totalMemoryMB / 1024).ToString("0.0")}GB");

    cpuCounter = new PerformanceCounter("Processor", "% Processor Time", "_Total");
    ramCounter = new PerformanceCounter("Memory", "Available MBytes");
}

🔴 当前代码

YF_RelayCommand.cs — 泛型版本
public bool CanExecute(object parameter) =>
    _canExecute?.Invoke((T)parameter) ?? true;       // ⚠️ InvalidCastException

public void Execute(object parameter) =>
    _execute((T)parameter);                            // ⚠️ InvalidCastException

🟢 修改建议

YF_RelayCommand.cs — 安全类型转换
public bool CanExecute(object parameter)
{
    if (parameter is T typedParam)
        return _canExecute?.Invoke(typedParam) ?? true;
    // 参数为 null 或类型不匹配时，如果可执行方法不需要参数则允许执行
    return _canExecute == null;
}

public void Execute(object parameter)
{
    if (parameter is T typedParam)
    {
        _execute(typedParam);
    }
    else if (parameter == null && default(T) == null)
    {
        // T 是引用类型且 parameter 为 null 时，调用 default(T)
        _execute(default(T));
    }
    // 类型不匹配时静默忽略，避免因 XAML 绑定问题导致崩溃
}

/// <summary>
/// 从指定路径加载插件程序集并获取其 UserControl 和 ViewModel 类型

private (Type userControlType, Type viewModelType, Assembly assembly)?
    LoadPluginTypes(string pluginDirectory)
{

        .Select(p => Path.GetFileNameWithoutExtension(p))
        .ToArray();

    foreach (string pluginName in dllFiles)

            continue;

        string assemblyPath = Path.Combine(pluginDirectory, $"{pluginName}.dll");
        byte[] assemblyBytes = File.ReadAllBytes(assemblyPath);
        Assembly assembly = Assembly.Load(assemblyBytes);

        Type userControlType = assembly.GetType($"{pluginName}.MainControl");
        Type viewModelType = assembly.GetType($"{pluginName}.MainControlViewModel");

        if (userControlType != null && viewModelType != null)
            return (userControlType, viewModelType, assembly);

                $"{pluginName} MainControlViewModel 加载失败");
    }
    return null;
}

💡 整体改进建议

1. 引入依赖注入容器
当前项目使用手写单例模式（Lazy<T> + Instance 属性）管理所有服务。随着插件数量增长，建议引入 DI 容器（如 Microsoft.Extensions.DependencyInjection）来管理服务生命周期、解析依赖关系，并提升可测试性。
2. 使用 AssemblyLoadContext 实现插件热卸载
当前使用 Assembly.LoadFrom 加载插件，程序集无法被卸载。.NET Core 提供了 AssemblyLoadContext，允许为每个插件创建独立的加载上下文，支持完全卸载插件并释放内存。这对于长时间运行的桌面应用非常重要。
3. 添加单元测试
项目中没有任何测试代码。考虑到框架核心逻辑（插件加载、日志系统、AOP拦截、RelayCommand）的复杂度，建议使用 xUnit + Moq 添加单元测试，确保重构和功能迭代时的回归安全。
4. 统一异步编程模型
项目中混用了 Thread、ThreadPool 和 DispatcherTimer。建议统一使用 async/await 模式，将耗时操作（如 WMI 查询）封装为 Task.Run，将 UI 更新保留在 Dispatcher 线程上。这样代码更简洁且不易产生线程安全问题。
5. 引入 CommunityToolkit.Mvvm
推荐引入 CommunityToolkit.Mvvm NuGet 包。它提供了源生成器驱动的 [ObservableProperty]、[RelayCommand] 等特性，可以大幅减少样板代码（INotifyPropertyChanged 实现、ICommand 实现），同时避免手写代码中的错误。
